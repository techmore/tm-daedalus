# Whole-run scanner comparisons

NmapUI emits a detailed result per host. Comparing only the last event can miss changes on every preceding host. Selection version 2 considers all bounded deep-result events from each explicit run, ordered by occurrence time and saved event ID. Each host's latest observation replaces its earlier port snapshot; old ports are not unioned into later results. Hosts observed in earlier phases remain observations from that run, not assertions of final reachability.

The comparison freezes its run cutoff, selected event IDs, invalid-event IDs, selection mode/version and an evidence anchor. The anchor is the greatest saved result ID, allowing a late upload with an earlier occurrence time to produce a new immutable comparison. Historical comparison rows remain unchanged; duplicate delivery does not create another row for the same evidence set. The last occurrence-time result remains separately identified in the evidence. No database migration or report-template change is involved.

Selection supports at most 10,000 detailed events, 64 MiB of payload evidence, 10,000 distinct hosts and 50,000 retained port observations per run. Exceeding a bound makes the comparison unavailable; the last host is not silently substituted for the whole run. Invalid result events are identified and prevent absence confirmation. Unknown target coverage remains unknown. Removal still requires equal explicitly reported target coverage, completed run status and complete per-host port coverage for ports. A successful tracked single-IP command can establish that one target under the existing strict command checks; it does not establish complete port coverage. Local runs without explicit coverage cannot confirm absence.

Source/API regressions exercise earlier-host changes with an unchanged last host, whole-port replacement, late earlier-time host uploads, immutable history, duplicate receipts, workspace isolation, 201 result events and event/byte/host/port bounds. These fixtures establish selection behavior; physical multi-VLAN/fleet validation and explicit local-run target/port coverage remain required.
